# 請求コード管理 設計書

## 1. 概要

### 1.1 目的
請求コード管理は、各LOB（Line of Business）が使用する請求コードを一元管理するためのマスタ機能である。
請求コードは費用種別・大分類・中分類・項目の4階層で構成され、LOBごとに異なる請求コード体系を保持する。

### 1.2 画面構成

- **ルート**: `/master/request-cd`
- **レイアウト**: ページコンテナ `w-full px-8 py-4`
- **ページタイトル**: `Master管理 / 請求コード管理`
- **認証**: 全ユーザーがアクセス可能（未認証時は `/login` へリダイレクト）

### 1.3 機能一覧

| No | 機能 | 説明 |
|----|------|------|
| 1 | 一覧表示 | 全請求コードをテーブル形式で表示（ページネーション付き） |
| 2 | 検索／フィルター | 適用範囲・費用種別・請求コード文字列での絞り込み |
| 3 | 編集 | モーダル画面から既存データの更新 |
| 4 | 新規登録 | モーダル画面から新規請求コードの作成 |
| 5 | 横スクロール | カラム数が多いためテーブル全体を横スクロール対応 |

## 2. データモデル

### 2.1 インターフェース定義

```typescript
interface ChargeCd {
  id: string;                 // 一意ID（CHG00001形式）
  scope: string;              // 適用範囲（LOB）
  feeTypeCd: string;          // 費用種別コード（A, B, C...）
  majorCd: string;            // 大分類コード（L01, L02...）
  mediumCd: string;           // 中分類コード（M01, M02...）
  itemCd: string;             // 項目コード（S001, S002...）
  feeType: string;            // 費用種別名
  major: string;              // 大分類名
  medium: string;             // 中分類名
  item: string;               // 項目名
  description: string;        // 内容
  unitPrice: number;          // 単価（負数可：割引）
  priceUnit: string;          // 単位（単価用）
  inputType: string;          // 入力区分
  taxCode: string;            // 税コード
  returnDiscountFlag: string; // 返還割引フラグ
  gsapAccountCd: string;      // GSAP 勘定科目コード
  hanaAccountCd: string;      // HANA 勘定科目コード
  detailCd: string;           // 細目コード
  optionalWorkFlag: string;   // オプション作業フラグ
  revenueMethod: string;      // 売上計上方法区分
  workTiming: string;         // 作業タイミング
  productSize: string;        // 商品サイズ
  sizeUnit: string;           // 単位（サイズ用）
  extendedStorage: string;    // 延長保管
  packagingSize: string;      // 梱包サイズ
  workDetailCd: string;       // 作業詳細区分
  productCategoryCd: string;  // 商品区分コード
}
```

### 2.2 請求コードの構成ルール

請求コードは4つのコード値をハイフン区切りで連結して表現する：

```
{費用種別コード}-{大分類コード}-{中分類コード}-{項目コード}
```

**例**:
- `A-L98-M01-S001` → 月額利用料 / 月額利用料調整 / 月額利用料調整 / 月額利用料調整
- `B-L01-M03-S999` → 標準 / 倉庫作業 / 出荷作業 / 出荷作業料割引き (ポスト投函)

**コード体系**:

| 階層 | コード範囲 | 例 |
|------|-----------|-----|
| 費用種別コード | A, B, C, D, E | A = 月額利用料, B = 標準 |
| 大分類コード | L01-L99 | L01 = 倉庫作業, L98 = 月額利用料調整 |
| 中分類コード | M01-M99 | M01 = 出荷作業, M03 = 出荷作業 |
| 項目コード | S001-S999 | S001 = 月額利用料調整, S999 = 各種割引 |

### 3.2 フィルター

- **適用範囲**（FilterSelect ドロップダウン）: 全店舗, RSL, RSL(1stParty), RSL(佐川), サテライトRSL, BOOKS
- **費用種別**（FilterSelect ドロップダウン）: 月額利用料, 標準, オプション, 特別, 割引
- **請求コード**（SearchInput フリーテキスト）: コード文字列の部分一致検索

### 3.3 操作

#### 編集（更新カラムの「編集」リンク）
1. 行の「編集」リンクをクリック → 編集モーダル表示
2. モーダル内の各フィールドを変更
3. 「保存」ボタンで更新、「取消」で破棄

#### 新規登録（「新規登録」ボタン）
1. フィルター行右端の「新規登録」ボタンをクリック
2. 編集モーダルと同様の入力フォームでデータ入力
3. 「登録」ボタンで保存（IDは自動採番）

#### 編集モーダルのフォーム仕様
- **レイアウト**: 3カラムグリッド（`md:grid-cols-3`）
- **スクロール**: 高さ制限（`max-h-[420px]`）+ 縦スクロール
- **入力方式**: コード体系の項目は `<select>` ドロップダウン、フリーテキスト項目は `<input>`
- **サイズ**: `size="2xl"`（DataTableのModalコンポーネント準拠）

## 4. モックデータ設計

### 4.1 データ件数
- **10,000 レコード**（マスタ系画面の標準に準拠）

### 4.2 コード体系定義

```typescript
適用範囲 = ["全店舗", "RSL", "RSL(1stParty)", "RSL(佐川)", "サテライトRSL", "BOOKS"]
費用種別 = ["月額利用料", "標準", "オプション", "特別", "割引"]
費用種別コード = ["A", "B", "C", "D", "E"]
大分類 = ["月額利用料調整", "倉庫作業", "出荷作業", "入荷作業", "保管作業", ...]
大分類コード = ["L98", "L01", "L02", "L03", "L04", "L05", "L06", "L07", "L08", "L99"]
中分類 = ["月額利用料調整", "出荷作業", "入荷作業", "保管作業", ...]
中分類コード = ["M01", "M02", "M03", "M04", "M05", "M06", "M07", "M08", "M09", "M99"]
項目 = ["月額利用料調整", "出荷作業料", "入荷作業料", ..., "出荷作業料割引き (ポスト投函)", ...]
項目コード = ["S001", "S002", "S003", "S004", "S005", "S006", "S007", "S008", "S009", "S010", "S999"]
```

### 4.3 データ生成ロジック
各カラムはループインデックス（`i % array.length`）で巡回的に値を割り当て、多様な組み合わせを生成する。単価は正負両方の値を含む（割引データの表現）。

## 9. 今後の拡張案
