# 配送日历 设计文档

> 2026-06-09 | 代引业务 配送日历页面重设计

## 概述

重写 `/delivery/calendar` 页面，从每月2个基准日（12/27）+2个衍生日（+2/+5）的简单结构，改为以 JP入金日 为唯一基准、佐川入金日/締日/支付预定日 为衍生日期的新结构。新增処理済み状态管理、新規作成、跨月修改功能。

---

## 数据模型

### ScheduleEntry

```ts
interface ScheduleEntry {
  id: string;           // "{year}-{month}-{index}" (0 or 1)
  year: number;
  month: number;        // 0-11
  jpDepositDate: string;    // "15" or "3/1" (跨月)
  sgDepositDate: string;    // "12" or "25"
  closingDate: string;      // "10" or "25"
  paymentDate: string;      // "31" or "4/30" (跨月)
  jpProcessed: boolean;
  sgProcessed: boolean;
}
```

- 日期字段使用字符串存储，支持 `"15"` 格式（当月某日）和 `"3/1"` 格式（跨月）
- 每月2条记录，id 后缀 0 和 1 区分
- 排序规则：先按 month，再按 id

---

## 默认值生成规则

新規作成时按以下规律生成 12 个月 × 2 = 24 条记录：

| 条目 | JP入金日 | 佐川入金日 | 締日 | 支付预定日 |
|------|---------|-----------|------|-----------|
| ① | 15 | 12 | 10 | 当月月末 |
| ② | 27 | 25 | 25 | 次月月末 |

- 支付预定日为月末时，自动计算当月/次月天数
- 12月条目②的支付日跨年到次年1月末
- 所有条目初始 jpProcessed = sgProcessed = false

## 功能清单

### ✨ 新規作成
- 弹窗输入年份
- 按默认规则生成 24 条记录
- 自动切换到新年份
- 已存在的年份提示不可重复创建

### 🖊 日期编辑
- 点击条目弹出 Modal
- 4 个日期字段独立编辑
- JP入金日/支付预定日支持跨月格式 `月/日`
- 保存后按 month+id 排序

### ✅ 処理済み
- 每条目 2 个按钮：JP 済 / 佐川 済
- 直接在卡片上点击切换，无需进入编辑
- 状态独立存储

### 🔔 次回入金日
- 顶部横幅显示最近未来入金日
- JP/佐川 并列显示 + 倒计时天数
- 对应月卡片蓝色高亮 + 脉冲动画

### 📊 年度切换
- 下拉选择已有年份
- 数据按年独立存储
